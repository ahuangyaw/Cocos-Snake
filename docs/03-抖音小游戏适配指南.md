## 二、安装抖音构建扩展（需要你操作）

### 方式 A：编辑器内的扩展管理器（推荐先试）

1. Cocos Creator 菜单 **`扩展` → `扩展管理器`**
2. 切到 **`商店`** 标签页
3. 搜索 **`抖音`** 或 **`字节`**
4. 找到官方的抖音小游戏构建扩展 → **安装**
5. 安装后 **重启编辑器**

### 方式 B：从 Cocos 资源商店下载

- [Cocos TikTok Builder（一键打包插件）](https://store.cocos.com/app/detail/9613)
- [douyin](https://store.cocos.com/app/detail/7875)

下载后在扩展管理器里「**导入扩展**」，或把扩展目录放到：

```
C:\Users\Administrator\.CocosCreator\extensions\          ← 全局（所有项目可用）
D:\project\cocos\2d\HelloWorld\extensions\                 ← 项目级
```

安装方式参考官方文档：[扩展的安装与分享](https://docs.cocos.com/creator/3.8/manual/zh/editor/extension/install.html)

### 验证装好了没

重启编辑器后，**构建发布**面板的「平台」下拉里应该出现 **`抖音小游戏`**（或 `ByteDance Mini Game`）。

**装好后告诉我**，我继续做剩下的构建配置与真机调试。

## 三、构建前的必做项（按优先级）

### ① 申请抖音小游戏 AppID（必须）

1. 打开 **抖音开放平台**：https://developer.open-douyin.com/
2. 用抖音账号登录 → **创建小游戏**
3. 提交主体信息（个人 / 企业，个人号有类目限制）
4. 拿到 **AppID**（形如 `ttxxxxxxxxxxxxxxxx`）
5. 下载 **抖音开发者工具**：用于真机预览与上传

> ⚠️ **建议尽早申请**，审核需要时间，别等游戏做完了才发现卡在这一步。

### ② 裁剪引擎模块（**体积优化最关键的一步**）

当前工程启用了 **22 个引擎模块**，但贪吃蛇只用到其中 6 个。

**位置**：`项目` → `项目设置` → `功能裁剪`

**贪吃蛇真正需要的（保留）**：

| 模块 | 用途 |
| --- | --- |
| `base` | 核心（必须有） |
| `2d` | 2D 渲染 |
| `ui` | Canvas / Label / Button |
| `graphics` | **程序化绘制**（蛇、棋盘、按钮全靠它） |
| `audio` | 音效 |
| `gfx-webgl` / `gfx-webgl2` | WebGL 渲染后端 |

**建议关闭的（白占体积）**：

| 模块 | 为什么可以关 |
| --- | --- |
| `spine-3.8` | 骨骼动画，本项目没用 |
| `dragon-bones` | 同上 |
| `tiled-map` | 瓦片地图，棋盘是自己画的 |
| `physics-2d-box2d` | 物理引擎，碰撞是自己算的（距离平方比较） |
| `particle-2d` | 粒子，特效是 Graphics 画的 |
| `video` | 视频播放 |
| `webview` | 内嵌网页 |
| `rich-text` | 富文本，只用普通 Label |
| `mask` | 遮罩 |
| `tween` | 缓动，动画是自己写的 |
| `intersection-2d` | 2D 相交检测，碰撞自己算 |
| `animation` | 关键帧动画，没用 |
| `affine-transform` | 仿射变换，没直接用 |

> **保守做法**：先关掉明显用不到的（spine / dragon-bones / tiled-map / video / webview / particle-2d），
> 构建一次看体积，再决定要不要继续裁。

### ③ 关闭性能监视器（**真机上会显示**）

`项目设置` 里有 `显示 FPS` 之类的调试开关；预览工具栏的 `Debug Mode` 也要设成 `None`。

**真机上那块的浮层会挡视角**，上线前务必关掉。

## 四、包体预算分析

### 当前体积（已实测）

| 类别 | 数量 | 大小 |
| --- | --- | --- |
| TypeScript 源码 | 10 个 | **132.7 KB** |
| 音频 wav | 11 个 | **355.3 KB** |
| 场景 | 1 个 | 7.9 KB |
| `.meta` | 26 个 | 5.0 KB（**不进包**） |
| **合计** | 48 个 | **500.9 KB** |

### 本项目在体积上的两个天然优势

**① 完全没有贴图资源**
蛇、棋盘、食物、按钮、粒子全部用 `Graphics` 程序化绘制。
所以**不需要任何图片**，也就没有"贴图压缩"这一步的烦恼。

**② 音效是代码合成的**
`tools/make_audio.js` 用振荡器 + 包络 + 扫频合成出 11 个 WAV（355 KB）。

### 音效还能不能更小？

可以。当前 WAV 是 **44.1kHz / 16bit / 单声道**。三个方向：

| 方案 | 预计体积 | 代价 |
| --- | --- | --- |
| 降采样到 22050Hz | ~178 KB | 高频细节损失；对"叮""嗒"这类音效基本听不出 |
| 转成 MP3/OGG | ~30-50 KB | 需要编码器（本机**没有 ffmpeg**）；小游戏平台对格式支持需实测 |
| **减少变体**：`eat_0..eat_5` 六个升调合并成 3 个 | 省 ~70 KB | 连击音阶变粗 |

**我建议先不优化音效** —— 355 KB 在首包预算里不算大头，而**引擎体积才是关键**（见第三节 ②）。
先裁引擎模块、构建一次看真实体积，再决定要不要动音频。

## 五、构建步骤（装好扩展后）

1. **项目** → **构建发布**
2. 平台选 **抖音小游戏**
3. 填 **AppID**
4. 关键选项：

| 选项 | 建议值 | 原因 |
| --- | --- | --- |
| 设备方向 | **portrait（竖屏）** | 我们的设计分辨率是 720×1280 |
| 设计分辨率 | 720 × 1280，**Fit Width** | 已在 `settings/v2/packages/project.json` 配好 |
| 初始场景 | `main` | |
| 资源服务器地址 | 先留空（本地包） | 首包能装下就不需要远程资源 |
| 调试模式 | **关闭** | 打开会显著增大体积并降低性能 |
| Source Maps | **关闭** | 上线不需要 |
| 压缩纹理 | 不需要 | 没有贴图 |

5. 点 **构建** → 产物在 `build/bytedance-mini-game/`
6. 用 **抖音开发者工具** 打开该目录 → 预览 / 上传
